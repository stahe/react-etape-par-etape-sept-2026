    8. Dialoguer avec le serveur

    Les exemples de ce chapitre interrogent le serveur JSON [RdvMedecins] : il doit être lancé ([npm run start:dev] dans le dossier [rdvmedecins-nestjs-json]), sur le port 8080, en même temps que le serveur de développement de [Vite], sur le port 5173.

    8.1. Exemple 22 : une première requête HTTP

    8.1.1. Le proxy du serveur de développement

    La page de l'exemple vient de http://localhost:5173 (le serveur de développement de [Vite]) ; l'API est sur http://localhost:8080. Pour un navigateur, ce sont deux origines différentes (le port fait partie de l'origine). Or, par sécurité, un navigateur n'autorise pas une page à lire les réponses d'une autre origine, sauf accord explicite du serveur (le mécanisme dit CORS). Et une requête vers une autre origine n'emporte pas les cookies (donc pas le jeton), sauf si le code le demande ([credentials: 'include']) ET que le serveur l'accepte, toujours par CORS.

    Plutôt que d'ouvrir le serveur aux autres origines, on fait passer les requêtes de l'API par le serveur de développement de [Vite]. C'est le proxy déclaré dans le fichier [vite.config.ts] des exemples (cf. exemple 01) :

// 22-fetch/src/App.tsx - une première requête HTTP vers le serveur
// -------------------------------------------------------------------------
// Le serveur JSON RdvMedecins doit être lancé (port 8080). On lui demande
// un captcha : GET /api/captcha -> { "id": "...", "svg": "<svg ...>" }.
//
//   - fetch(url) : la fonction du navigateur qui envoie une requête HTTP.
//     Elle renvoie une PROMESSE de la réponse ; reponse.json() une promesse
//     du corps, converti depuis le JSON. React n'a pas de client HTTP à lui ;
//   - l'adresse est RELATIVE (/api/captcha) : la requête part vers le
//     serveur de la page, celui de Vite (port 5173), qui la transmet au
//     serveur JSON (port 8080) grâce à son proxy (cf. vite.config.ts) ;
//   - trois états à afficher : en cours, réussi, en erreur.
// =========================================================================

import { useEffect, useState } from 'react';

// ce que renvoie GET /api/captcha
interface Captcha {
  id: string;
  svg: string;
}

const styleCaptcha = { display: 'inline-block', border: '1px solid #dee2e6', borderRadius: '0.375rem' };

export default function App() {
  const [captcha, setCaptcha] = useState<Captcha | null>(null);
  const [enCours, setEnCours] = useState(true);
  const [erreur, setErreur] = useState<string | null>(null);
  const [nbRequetes, setNbRequetes] = useState(0);
  // chaque clic sur "Autre image" change ce numéro, ce qui relance l'effet
  const [demande, setDemande] = useState(0);

  useEffect(() => {
    // AbortController : le moyen d'ANNULER une requête en cours
    const annulation = new AbortController();
    setEnCours(true);
    setErreur(null);
    fetch('/api/captcha', { signal: annulation.signal })
      .then(async (reponse) => {
        // fetch ne rejette PAS une réponse d'erreur (4xx, 5xx) : on teste ok
        if (!reponse.ok) {
          throw new Error(`le serveur a répondu ${reponse.status} ${reponse.statusText}`);
        }
        const c = (await reponse.json()) as Captcha;
        setCaptcha(c);
        setNbRequetes((n) => n + 1);
        setEnCours(false);
      })
      .catch((e: Error) => {
        if (e.name === 'AbortError') return; // requête annulée : rien à afficher
        setErreur(e.message);
        setCaptcha(null);
        setEnCours(false);
      });
    // le nettoyage ANNULE la requête si l'effet est relancé ou si le
    // composant disparaît avant la réponse. En développement, StrictMode
    // exécute l'effet deux fois au démarrage : la première requête est
    // annulée (onglet Réseau : "canceled"), seule la seconde compte.
    return () => annulation.abort();
  }, [demande]);

  return (
    <div className="container py-4" style={{ maxWidth: 640 }}>
      <h1 className="h3 mb-3">Exemple 22 - une première requête HTTP</h1>
      <div className="card p-3">
        {enCours && <p className="text-muted">Chargement...</p>}
        {erreur && (
          <div className="alert alert-danger mb-3">
            Impossible d'obtenir un captcha : {erreur}.<br />
            Le serveur JSON RdvMedecins est-il lancé (port 8080) ?
          </div>
        )}
        {captcha && !enCours && (
          <>
            {/* dangerouslySetInnerHTML : insérer une chaîne comme du HTML */}
            <div className="mb-2"><div style={styleCaptcha} dangerouslySetInnerHTML={{ __html: captcha.svg }} /></div>
            <p className="small text-muted">id : <code>{captcha.id}</code></p>
          </>
        )}
        <button className="btn btn-primary align-self-start" disabled={enCours} onClick={() => setDemande((d) => d + 1)}>
          Autre image
        </button>
        <p className="small text-muted mt-2 mb-0">
          {nbRequetes} requête(s) réussie(s) - ouvrez l'onglet Réseau des outils de développement (F12).
        </p>
      </div>
    </div>
  );
}
    • lignes 19-22 : ce que renvoie [GET /api/captcha] ;
    • lignes 27-30 : trois états à afficher : en cours, réussi (le captcha), en erreur ;
    • ligne 32 : un numéro de demande : chaque clic sur « Autre image » l'augmente, ce qui relance l'effet ;
    • lignes 34-61 : la requête est un effet : elle synchronise le composant avec le serveur, au premier affichage puis à chaque nouvelle demande :
      • ligne 36 : un [AbortController] permet d'annuler une requête en cours : on passe son [signal] à [fetch] ;
      • ligne 39 : [fetch(url)] envoie une requête GET et renvoie une promesse de la réponse. L'adresse est RELATIVE : la requête part vers le serveur de la page, celui de [Vite], qui la transmet au serveur JSON ;
      • lignes 42-44 : ATTENTION : [fetch] ne rejette PAS une réponse d'erreur (4xx, 5xx) ; sa promesse n'est rejetée que si AUCUNE réponse n'arrive (réseau coupé). On teste donc [reponse.ok] (vrai pour un code 2xx) ;
      • ligne 45 : [reponse.json()] lit le corps et le convertit depuis le JSON (encore une promesse). [as Captcha] : on affirme à [TypeScript] la forme des données reçues : il ne peut pas le vérifier ;
      • lignes 50-55 : une erreur ; [AbortError] : la requête a été annulée, il n'y a rien à afficher ;
      • ligne 60 : le nettoyage ANNULE la requête si l'effet est relancé ou si le composant disparaît avant la réponse. En développement, [<StrictMode>] exécute l'effet deux fois au démarrage : la première requête est annulée (l'onglet Réseau l'indique « canceled »), seule la seconde compte ;
    • ligne 77 : l'image est un morceau de SVG, une chaîne à insérer comme du HTML. [{captcha.svg}] afficherait le texte [<svg ...>], échappé. [dangerouslySetInnerHTML] insère la chaîne telle quelle : son nom rappelle le danger. À n'utiliser QUE pour un contenu sûr : ce SVG est fabriqué par NOTRE serveur. Avec une saisie d'utilisateur, ce serait ouvrir la porte à l'injection de scripts ;
    • ligne 81 : une nouvelle demande : l'effet est relancé.

    Si le serveur JSON est arrêté, le proxy de [Vite] répond 500 : « Impossible d'obtenir un captcha : le serveur a répondu 500 Internal Server Error ».

// 23-connexion/src/App.tsx - se connecter au serveur RdvMedecins
// -------------------------------------------------------------------------
//   1. au démarrage : GET /api/auth/moi - sommes-nous déjà connectés ?
//      (après un F5, le client a tout oublié ; le serveur, lui, lit le cookie) ;
//   2. connexion : POST /api/auth/login, corps JSON { login, password,
//      captchaId, captcha }. En cas de succès, le serveur dépose le cookie
//      httpOnly du jeton JWT : notre code ne le voit JAMAIS (essayez
//      document.cookie dans la console : il n'y est pas) ;
//   3. requête protégée : GET /api/medecins. Le navigateur y joint le cookie
//      tout seul (même origine) ;
//   4. déconnexion : POST /api/auth/logout - le serveur efface le cookie.
//
// Le formulaire utilise les ACTIONS de React 19 : <form action={fonction}>.
// Au lieu de gérer onSubmit et chaque champ, on reçoit toutes les valeurs
// du formulaire (FormData), et useActionState mémorise le résultat de la
// dernière action (ici, un message d'erreur) et dit si elle est en cours.
//
// Un cookie appartient à une machine (localhost) et à un chemin (/api) : il
// est donc commun à TOUS les exemples. Une fois connecté ici, les exemples
// 24 et 25 le sont aussi.
// =========================================================================

import { useActionState, useEffect, useState } from 'react';
import { useFormStatus } from 'react-dom';

interface Utilisateur {
  login: string;
  nom: string;
  role: 'ADMIN' | 'DOCTOR' | 'USER';
}
interface Medecin {
  id: number;
  titre: string;
  prenom: string;
  nom: string;
}
interface Captcha {
  id: string;
  svg: string;
}
// la forme de TOUTES les erreurs de l'API
interface ErreurApi {
  statusCode: number;
  cle: string;
  params?: Record<string, string>;
}

// les quelques messages dont cet exemple a besoin (l'exemple 25 utilisera i18next)
const MESSAGES: Record<string, string> = {
  'LOGIN.ERROR': 'Login ou mot de passe incorrect.',
  'ERRORS.WRONG_CAPTCHA': "Les caractères recopiés ne correspondent pas à l'image.",
  'ERRORS.TOO_MANY_ATTEMPTS': 'Trop de tentatives infructueuses. Réessayez plus tard.',
};

// une requête GET, dont la réponse JSON est typée ; une erreur si ce n'est pas un 2xx
async function lire<T>(url: string): Promise<T> {
  const reponse = await fetch(url);
  if (!reponse.ok) {
    throw reponse; // on "lance" la réponse elle-même : son statut dira quoi faire
  }
  return (await reponse.json()) as T;
}

// le bouton d'envoi : useFormStatus() dit si le formulaire QUI LE CONTIENT
// est en cours d'envoi (il doit donc être un composant à part, placé dedans)
function BoutonConnexion() {
  const { pending } = useFormStatus();
  return <button className="btn btn-primary" disabled={pending}>{pending ? 'Connexion...' : 'Se connecter'}</button>;
}

// le résultat de la dernière tentative de connexion
interface EtatConnexion {
  erreur: string | null;
  login: string; // le login tapé, pour le réafficher
}

export default function App() {
  const [utilisateur, setUtilisateur] = useState<Utilisateur | null>(null);
  const [medecins, setMedecins] = useState<Medecin[]>([]);
  const [captcha, setCaptcha] = useState<Captcha | null>(null);
  const [pret, setPret] = useState(false); // la vérification de départ est-elle terminée ?
  const [erreurServeur, setErreurServeur] = useState<string | null>(null);

  async function chargerCaptcha() {
    setCaptcha(await lire<Captcha>('/api/captcha'));
  }

  async function chargerMedecins() {
    setMedecins(await lire<Medecin[]>('/api/medecins'));
  }

  // 1. qui est connecté ? 200 -> l'utilisateur ; 401 -> personne
  useEffect(() => {
    async function verifierSession() {
      try {
        setUtilisateur(await lire<Utilisateur>('/api/auth/moi'));
        await chargerMedecins();
      } catch (e) {
        if (!(e instanceof Response) || e.status !== 401) {
          setErreurServeur('Le serveur JSON RdvMedecins est-il lancé (port 8080) ?');
        } else {
          await chargerCaptcha();
        }
      }
      setPret(true);
    }
    verifierSession();
  }, []);

  // 2. la connexion : une ACTION, qui reçoit l'état précédent et les
  // données du formulaire, et renvoie le nouvel état
  async function seConnecter(_precedent: EtatConnexion, donnees: FormData): Promise<EtatConnexion> {
    const login = String(donnees.get('login'));
    const reponse = await fetch('/api/auth/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' }, // le corps est du JSON
      body: JSON.stringify({ login, password: donnees.get('password'), captchaId: captcha?.id, captcha: donnees.get('captcha') }),
    });
    if (!reponse.ok) {
      // le corps JSON de la réponse d'erreur
      const erreur = (await reponse.json().catch(() => null)) as ErreurApi | null;
      const cle = erreur?.cle ?? 'ERRORS.SERVER_UNREACHABLE';
      await chargerCaptcha(); // chaque image ne sert qu'une fois
      return { erreur: `${reponse.status} - ${MESSAGES[cle] ?? cle}`, login };
    }
    setUtilisateur((await reponse.json()) as Utilisateur);
    await chargerMedecins();
    return { erreur: null, login };
  }
  const [etat, actionConnexion] = useActionState(seConnecter, { erreur: null, login: 'admin' });

  // 4. la déconnexion
  async function seDeconnecter() {
    await fetch('/api/auth/logout', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: '{}' });
    setUtilisateur(null);
    setMedecins([]);
    await chargerCaptcha();
  }

  let contenu;
  if (!pret) {
    contenu = <p className="text-muted">Vérification de la session...</p>;
  } else if (utilisateur) {
    // connecté
    contenu = (
      <div className="card p-3">
        <p>
          Connecté : <strong>{utilisateur.nom}</strong> ({utilisateur.login}), rôle{' '}
          <span className="badge text-bg-primary">{utilisateur.role}</span>
        </p>
        <h2 className="h6">GET /api/medecins</h2>
        <ul>
          {medecins.map((m) => <li key={m.id}>{m.titre} {m.prenom} {m.nom}</li>)}
        </ul>
        <p className="small text-muted">Rechargez la page (F5) : vous restez connecté.</p>
        <button className="btn btn-outline-secondary align-self-start" onClick={seDeconnecter}>Se déconnecter</button>
      </div>
    );
  } else if (!erreurServeur) {
    // pas connecté : le formulaire. Les champs ne sont PAS contrôlés : name
    // les désigne dans FormData ; après chaque action, React les remet à
    // leur valeur de départ (defaultValue)
    contenu = (
      <form className="card p-3" action={actionConnexion}>
        <div className="mb-2">
          <label className="form-label" htmlFor="login">Login</label>
          <input id="login" name="login" className="form-control" autoComplete="username" defaultValue={etat.login} />
        </div>
        <div className="mb-2">
          <label className="form-label" htmlFor="password">Mot de passe</label>
          <input id="password" name="password" type="password" className="form-control" autoComplete="current-password" />
        </div>
        <div className="mb-3">
          <label className="form-label" htmlFor="captcha">Recopiez les caractères de l'image</label>
          <div className="d-flex align-items-center gap-3 mb-2">
            <div dangerouslySetInnerHTML={{ __html: captcha?.svg ?? '' }} />
            <button type="button" className="btn btn-link btn-sm" onClick={chargerCaptcha}>Autre image</button>
          </div>
          <input id="captcha" name="captcha" className="form-control" autoComplete="off" />
        </div>
        <BoutonConnexion />
        <p className="small text-muted mt-2 mb-0">Comptes : admin, pelissier, martin... (mot de passe = login).</p>
        {etat.erreur && <div className="alert alert-danger mt-3 mb-0">{etat.erreur}</div>}
      </form>
    );
  }

  return (
    <div className="container py-4" style={{ maxWidth: 640 }}>
      <h1 className="h3 mb-3">Exemple 23 - connexion au serveur</h1>
      {contenu}
      {erreurServeur && <div className="alert alert-danger mt-3">{erreurServeur}</div>}
    </div>
  );
}

    Le déroulement (lignes 4-12) : au démarrage, on demande au serveur qui est connecté ; puis connexion, requête protégée, déconnexion.

    • lignes 27-47 : quelques types de l'API, dont la forme de TOUTES ses erreurs ;
    • lignes 50-54 : les quelques messages dont cet exemple a besoin, pour traduire les clés du serveur (l'exemple 25 utilisera [i18next]) ;
    • lignes 57-63 : une petite fonction générique pour les requêtes GET : la réponse JSON, typée ; et, si ce n'est pas un 2xx, on « lance » la réponse elle-même : son statut dira quoi faire ;
    • lignes 67-70 : le bouton d'envoi du formulaire. [useFormStatus()] (de [react-dom]) dit si le formulaire QUI LE CONTIENT est en cours d'envoi : ce doit donc être un composant à part, placé dans le formulaire ;
    • lignes 94-109 : au démarrage, [GET /api/auth/moi] : sommes-nous déjà connectés ? Après un F5, le client a tout oublié ; le serveur, lui, lit le cookie. 200 : l'utilisateur ; 401 : personne (on charge alors un captcha) ; autre chose : le serveur ne répond pas. Une fonction [async] ne peut pas être l'effet lui-même (un effet renvoie son nettoyage, pas une promesse) : on la déclare dans l'effet, puis on l'appelle ;
    • lignes 113-130 : la connexion, écrite comme une action de [React] 19 (cf. plus bas). Elle reçoit l'état précédent et les données du formulaire ([FormData]), et renvoie le nouvel état :
      • ligne 114 : [donnees.get(nom)] lit un champ du formulaire, désigné par son attribut [name] ;
      • lignes 115-119 : [POST /api/auth/login], avec un corps JSON : [method], l'entête [Content-Type] et le corps, fabriqué par [JSON.stringify]. En cas de succès, le serveur dépose le cookie [httpOnly] du jeton JWT : notre code ne le voit JAMAIS (essayez [document.cookie] dans la console : il n'y est pas) ;
      • lignes 120-126 : un échec : le corps JSON de la réponse d'erreur donne la clé du message ; chaque image de captcha ne sert qu'une fois : on en charge une autre ;
      • lignes 127-129 : un succès : l'utilisateur, puis une requête protégée, [GET /api/medecins] : le navigateur y joint le cookie tout seul (même origine) ;
    • ligne 131 : [useActionState(action, étatInitial)] ([React] 19) renvoie l'état produit par la dernière exécution de l'action, et une version de l'action à donner au formulaire ;
    • lignes 134-139 : la déconnexion, [POST /api/auth/logout] : le serveur efface le cookie. Tout POST doit avoir un corps JSON (le serveur refuse les autres, cf. chapitre précédent) : ['{}'] ;
    • ligne 165 : [<form action={fonction}>] : depuis [React] 19, l'attribut [action] d'un formulaire peut recevoir une fonction. À l'envoi, [React] empêche l'envoi par le navigateur, réunit les champs dans un [FormData], et appelle la fonction, pendant laquelle [useFormStatus] indique « en cours ». Plus besoin de [onSubmit], de [preventDefault], ni d'un état par champ ;
    • lignes 168-180 : les champs ne sont PAS contrôlés : [name] les désigne dans le [FormData]. Après chaque action, [React] remet le formulaire à zéro : chaque champ reprend sa valeur de départ ([defaultValue]). Le mot de passe et le captcha sont donc vidés ; le login reprend la valeur rangée dans l'état par l'action ([etat.login]), c'est-à-dire celle qui vient d'être tapée ;
    • ligne 184 : le message d'erreur produit par la dernière action.

// commun/erreur-api.ts - UNE classe pour toutes les erreurs de l'API
// -------------------------------------------------------------------------
// Toutes les réponses d'erreur du serveur RdvMedecins ont la même forme :
//   { "statusCode": 409, "cle": "ERRORS.LOGIN_TAKEN", "params": {...}, "champs": {...} }
// Mais une requête peut aussi échouer AUTREMENT : pas de réponse du tout
// (réseau coupé : fetch lance une TypeError), ou une réponse qui ne vient
// pas de notre serveur (une page d'erreur du proxy de Vite quand le
// serveur JSON est arrêté). On convertit tout cela en UNE classe,
// ErreurApi, qui porte la clé de traduction envoyée par le serveur (et,
// s'il y en a, ses paramètres et l'erreur de chaque champ).
// =========================================================================

export class ErreurApi extends Error {
  readonly statusCode: number; // 0 : le serveur n'a pas répondu
  readonly cle: string; // ex : 'ERRORS.LOGIN_TAKEN'
  readonly params: Record<string, string>;
  readonly champs: Record<string, string>;

  constructor(statusCode: number, cle: string, params: Record<string, string> = {}, champs: Record<string, string> = {}) {
    super(cle);
    this.name = 'ErreurApi';
    this.statusCode = statusCode;
    this.cle = cle;
    this.params = params;
    this.champs = champs;
  }
}

// une réponse d'erreur (4xx, 5xx) -> une ErreurApi
export async function depuisReponse(reponse: Response): Promise<ErreurApi> {
  // le corps JSON de l'erreur, s'il existe et a la bonne forme
  let corps: { cle?: string; params?: Record<string, string>; champs?: Record<string, string> } = {};
  try {
    const json: unknown = await reponse.json();
    if (typeof json === 'object' && json !== null) {
      corps = json;
    }
  } catch {
    // pas du JSON : ce n'est pas notre serveur qui a répondu
  }
  // pas de clé : le proxy ou le réseau ont répondu à sa place
  const cle = corps.cle ?? (reponse.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR');
  return new ErreurApi(reponse.status, cle, corps.params, corps.champs);
}
    • lignes 14-28 : UNE classe pour toutes les erreurs de l'API : le statut HTTP (0 : pas de réponse), la clé de traduction envoyée par le serveur, ses paramètres, et l'erreur de chaque champ d'un formulaire refusé. Elle hérite d'[Error] : on peut la lancer ([throw]) et la reconnaître ([instanceof ErreurApi]). On n'utilise pas les « paramètres propriétés » de [TypeScript] ([constructor(public readonly cle: string)]) : l'option [erasableSyntaxOnly] du [tsconfig.json] les interdit, parce qu'ils produisent du code ;
    • lignes 31-45 : une réponse d'erreur devient une [ErreurApi]. Le corps n'est pas toujours du JSON de notre serveur : quand le serveur JSON est arrêté, c'est le proxy de [Vite] qui répond, sans corps JSON. Pas de clé : un statut 500 ou plus signifie « serveur injoignable ».

// -------------------------------------------------------------------------
// Dans l'exemple 23, chaque requête répétait les mêmes gestes : préfixe
// /api, entête JSON, test de response.ok, lecture du corps d'erreur... On
// les regroupe ici :
//
//   const medecins = await api.get<Personne[]>('/medecins');
//   await api.post('/rendez-vous', { jour, idCreneau, idClient });
//
//   - en cas de succès, la promesse renvoie le corps JSON, TYPÉ ;
//   - en cas d'échec, elle est REJETÉE avec une ErreurApi.
// Toutes les requêtes passent par la fonction requete : c'est l'endroit
// où l'on traiterait un problème COMMUN à toutes (cf. l'étude de cas et la
// réponse 401). Utilisé par les exemples 24 et 25.

import { depuisReponse, ErreurApi } from './erreur-api';

export async function requete<T>(methode: string, url: string, corps?: unknown): Promise<T> {
  let reponse: Response;
  try {
    reponse = await fetch(`/api${url}`, {
      method: methode,
      // un corps JSON (le serveur refuse un POST qui n'en est pas un)
      headers: corps === undefined ? {} : { 'Content-Type': 'application/json' },
      body: corps === undefined ? undefined : JSON.stringify(corps),
    });
  } catch {
    // fetch n'a obtenu AUCUNE réponse (réseau, serveur arrêté)
    throw new ErreurApi(0, 'ERRORS.SERVER_UNREACHABLE');
  }
  if (!reponse.ok) {
    throw await depuisReponse(reponse);
  }
  return (await reponse.json()) as T;
}

export const api = {
  get: <T>(url: string) => requete<T>('GET', url),
  // un POST a toujours un corps JSON : {} par défaut
  post: <T>(url: string, corps: unknown = {}) => requete<T>('POST', url, corps),
  put: <T>(url: string, corps: unknown) => requete<T>('PUT', url, corps),
  delete: <T>(url: string, corps?: unknown) => requete<T>('DELETE', url, corps),
};

// -------------------------------------------------------------------------
// La gestion des clients (compte admin). Ce formulaire ne fait
// VOLONTAIREMENT aucune validation dans le navigateur : tout est envoyé
// au serveur, qui répond, en cas de refus, par une erreur JSON (convertie
// en ErreurApi par commun/api.ts) :
//
//   400 { cle: 'ERRORS.INVALID_FORM', champs: { nom: 'ERRORS.LASTNAME_REQUIRED' } }
//   409 { cle: 'ERRORS.PATIENT_ALREADY_EXISTS', champs: { prenom: ..., nom: ... } }
//   409 { cle: 'ERRORS.CONCURRENT_UPDATE' }         (verrou optimiste)
//
// L'erreur de CHAQUE champ (ErreurApi.champs) est rangée dans l'état et
// affichée sous le champ ; son message est la CLÉ envoyée par le serveur,
// que le composant traduit (i18next). Modifier un champ efface son erreur.
// Essayez : un nom vide, un titre "Dr", un homonyme (Alice DURAND), un
// login déjà pris (martin), la même fiche modifiée dans deux onglets...
// =========================================================================

import { useState, useTransition, type FormEvent } from 'react';
import { useTranslation } from 'react-i18next';
import { api } from '../../commun/api';
import BarreConnexion from '../../commun/BarreConnexion';
import { ErreurApi } from '../../commun/erreur-api';
import type { Personne, Utilisateur } from '../../commun/types';
import { useConfirmation } from '../../16-confirmation/src/confirmation/confirmation';

interface SaisieClient {
  titre: string;
  prenom: string;
  nom: string;
  login: string;
  password: string;
  version: number;
}
type Champ = keyof SaisieClient;

const VIDE: SaisieClient = { titre: 'Mr', prenom: '', nom: '', login: '', password: '', version: 0 };

interface Message {
  cle: string;
  params?: Record<string, string>;
}

export default function App() {
  const { t, i18n } = useTranslation();
  const confirmer = useConfirmation();

  const [utilisateur, setUtilisateur] = useState<Utilisateur | null>(null);
  const [clients, setClients] = useState<Personne[]>([]);
  const estAdmin = utilisateur?.role === 'ADMIN';

  // le formulaire : idEdite === null -> création, sinon modification
  const [idEdite, setIdEdite] = useState<number | null>(null);
  const [saisie, setSaisie] = useState<SaisieClient>(VIDE);
  // l'erreur de chaque champ (une CLÉ de traduction), renvoyée par le serveur
  const [erreurs, setErreurs] = useState<Partial<Record<Champ, string>>>({});
  // le message général de la dernière erreur, et celui d'un succès
  const [erreurPage, setErreurPage] = useState<ErreurApi | null>(null);
  const [succes, setSucces] = useState<Message | null>(null);
  // useTransition : isPending est vrai pendant l'exécution de l'action
  // passée à startTransition - ici, l'envoi au serveur
  const [envoiEnCours, startTransition] = useTransition();

  async function recharger() {
    setClients(await api.get<Personne[]>('/clients'));
  }

  async function surConnexion(u: Utilisateur | null) {
    setUtilisateur(u);
    setClients([]);
    if (u?.role === 'ADMIN') {
      await recharger();
    }
  }

  function effacerMessages() {
    setErreurs({});
    setErreurPage(null);
    setSucces(null);
  }

  function nouveau() {
    setIdEdite(null);
    setSaisie(VIDE);
    effacerMessages();
  }

  function editer(c: Personne) {
    setIdEdite(c.id);
    // la VERSION lue avec la fiche repart avec la modification : si quelqu'un
    // a modifié la fiche entre-temps, le serveur répondra 409 CONCURRENT_UPDATE
    setSaisie({ titre: c.titre, prenom: c.prenom, nom: c.nom, login: c.login ?? '', password: '', version: c.version });
    effacerMessages();
  }

  // un champ modifié : sa valeur change, son erreur disparaît
  function modifier(champ: Champ, valeur: string) {
    setSaisie((s) => ({ ...s, [champ]: valeur }));
    setErreurs((e) => ({ ...e, [champ]: undefined }));
  }

  function enregistrer(evenement: FormEvent<HTMLFormElement>) {
    evenement.preventDefault();
    effacerMessages();
    // une transition ASYNCHRONE (React 19) : envoiEnCours reste vrai jusqu'à
    // la fin de la fonction
    startTransition(async () => {
      try {
        const client =
          idEdite === null
            ? await api.post<Personne>('/clients', saisie)
            : await api.put<Personne>(`/clients/${idEdite}`, saisie);
        nouveau(); // formulaire vidé, messages effacés...
        // ... sauf celui-ci
        setSucces({
          cle: idEdite === null ? 'FORM.AJOUTE' : 'FORM.MODIFIE',
          params: { nom: `${client.prenom} ${client.nom}`, login: client.login ?? '' },
        });
        await recharger();
      } catch (e) {
        if (!(e instanceof ErreurApi)) {
          throw e;
        }
        setErreurPage(e); // le message général
        setErreurs(e.champs); // l'erreur de chaque champ
      }
    });
  }

  async function supprimer(c: Personne) {
    const nom = `${c.prenom} ${c.nom}`;
    if (!(await confirmer(t('FORM.CONFIRMER_SUPPRESSION', { nom })))) {
      return;
    }
    effacerMessages();
    try {
      await api.delete(`/clients/${c.id}`);
      setSucces({ cle: 'FORM.SUPPRIME', params: { nom } });
    } catch (e) {
      setErreurPage(e instanceof ErreurApi ? e : null);
    }
    await recharger();
  }

  // un champ de saisie, avec son erreur traduite
  function champ(nom: 'prenom' | 'nom' | 'login' | 'password', type = 'text') {
    const erreur = erreurs[nom];

        {/* le message d'une erreur du serveur est une CLÉ : on la traduit */}
        {erreur && <div className="invalid-feedback">{t(erreur)}</div>}
      </>
    );
  }

  return (
    <div className="container py-4">
      <div className="d-flex justify-content-between align-items-center mb-3">
        <h1 className="h3 mb-0">Exemple 25 - les erreurs renvoyées par le serveur</h1>
        <select className="form-select form-select-sm w-auto" value={i18n.language} onChange={(e) => i18n.changeLanguage(e.target.value)}>
          <option value="fr">FR</option>
          <option value="en">EN</option>
        </select>
      </div>
      <BarreConnexion onUtilisateurChange={surConnexion} />
      {utilisateur && !estAdmin && <p className="alert alert-warning">{t('FORM.ADMIN_SEULEMENT')}</p>}

          <div className="col-lg-6">
            <table className="table table-sm align-middle">
              <tbody>
                {clients.map((c) => (
                  <tr key={c.id}>
                    <td>{c.titre} {c.prenom} {c.nom}</td>
                    <td><code>{c.login}</code></td>
                    <td className="text-end text-nowrap">
                      <button className="btn btn-sm btn-outline-primary me-1" onClick={() => editer(c)}>{t('FORM.MODIFIER')}</button>
                      <button className="btn btn-sm btn-outline-danger" onClick={() => supprimer(c)}>{t('FORM.SUPPRIMER')}</button>
                    </td>
                  </tr>
                ))}
              </tbody>
            </table>
          </div>

          <div className="col-lg-6">
            <form className="card p-3" noValidate onSubmit={enregistrer}>
              <h2 className="h5">{t(idEdite === null ? 'FORM.TITRE_AJOUT' : 'FORM.TITRE_MODIF')}</h2>
              <div className="mb-2">
                <label className="form-label" htmlFor="titre">{t('FORM.TITRE')}</label>

                  <option>Mr</option><option>Mme</option><option>Melle</option><option>Dr</option>
                </select>
                {erreurs.titre && <div className="invalid-feedback">{t(erreurs.titre)}</div>}
              </div>
              <div className="row g-2 mb-2">
                <div className="col-sm-6">{champ('prenom')}</div>
                <div className="col-sm-6">{champ('nom')}</div>
              </div>
              <div className="row g-2 mb-3">
                <div className="col-sm-6">{champ('login')}</div>
                <div className="col-sm-6">{champ('password', 'password')}</div>
              </div>
              <div className="d-flex gap-2">
                <button className="btn btn-primary" disabled={envoiEnCours}>{t('FORM.ENREGISTRER')}</button>
                <button type="button" className="btn btn-secondary" onClick={nouveau}>{t('FORM.ANNULER')}</button>
              </div>
              {succes && <div className="alert alert-success mt-3 mb-0">{t(succes.cle, succes.params)}</div>}
              {/* le message général, et le statut HTTP, pour comprendre */}

                  {t(erreurPage.cle, erreurPage.params)}{' '}
                  <span className="small text-muted">({erreurPage.statusCode} {erreurPage.cle})</span>
                </div>
              )}
            </form>
          </div>
        </div>
      )}
    </div>
  );
}
